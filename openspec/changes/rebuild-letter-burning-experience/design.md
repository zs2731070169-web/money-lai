## Context

动机与产品范围见 `proposal.md`，可验收行为见本变更的十份 delta spec。当前代码是回滚“心事升腾”后的钱包抽钞应用：`Game` 同时编排翻盖、抽钞、里程表、元进程、音频与画布；平台能力集中在同步的 `PlatformAdapter`；持久化仍是旧 `money-lai/state/v1`；渲染、状态机和大部分音频已具备纯函数测试与记录型 Canvas 测试。

本次是产品域替换，而非在钱包玩法上继续叠加。可复用的基础设施包括 Canvas DPR/安全区、帧循环、平台适配边界、程序化钢琴、Web Audio 防爆音，以及图鉴/双槽外观/成就的纯状态组织方式；钱包、现金和金额语义退出，元进程改造成明信片内容后接入新编排。

## Goals / Non-Goals

**Goals:**

- 用独立纯状态机表达 `IDLE → DRAW → FRONT → EDIT → EDIT_RETURN → BACK → DRAG → BURN → FADE → SILENCE → STAT → IDLE`，将手势、不可中断阶段和所有时长锁进测试。
- 用户文字只进入内存中的当前明信片与版本化本机手帐，类型和接口层面禁止进入计数请求。
- 火焰只由连续遮罩、纸缘和径向渐变构成，无粒子对象、无残留载体，且满足 60fps 热路径预算。
- iOS 键盘、持久化、临时文件系统分享、音频会话与网络均通过 `PlatformAdapter`，`src/core/` 保持平台无关。
- 旧数据可安全回滚：新版本使用新存储键，旧钱包状态不迁移成手帐，也不在本次删除。
- 将里程、独立图鉴、外观和成就改造成信封/明信片语义；只在菜单内查看，并与主界面无常驻数字、燃烧过程不受打断的约束共存。

**Non-Goals:**

- 账号、登录、CloudKit、跨设备同步、用户文本服务端备份或分享单条文字。
- AI 对话、情绪分析、测评、诊断、个性化推荐和动态生成图案。
- Android 的系统分享专项适配与服务端生产部署凭据；本次实现通用接口与 iOS/Web 路径，生产环境配置由发布流程注入。
- 延续钱包、金额、抽钞或心事升腾交互；旧皮肤和成就数据也不自动换算为燃信解锁。

## Decisions

### 1. 新编排替换旧 `Game` 消费链，基础设施按需复用

保留 `Game` 作为唯一帧循环与副作用编排入口，内部持有燃信状态、当前明信片资产、手帐、明信片里程、图鉴、信封/纸纹外观、成就、菜单页面和声景。新增 `src/core/letter/`、`src/core/journal/`、`src/core/count/` 纯函数模块；将 `src/core/meta/` 中可复用的集合/解锁模式重写为燃信模型；新画师放入 `src/core/render/`，平台实现仍位于 `src/adapters/`。

备选是在旧 `CashDrawState` 和 `WalletFlapState` 上改名扩展。两套状态的阈值、物理语义和结算点都不同，复用会保留大量无意义分支，因此不采用。

### 2. 主循环使用事件驱动纯状态机

状态机接收归一化触点、视口高度、时间推进和平台输入结果，输出状态与效果：请求文本输入、开始/停止声部、保存手帐、提交匿名计数、闪菜单入口。`DRAW` 负责从信封抽出；展开完成后自动进入 `EDIT` 全屏书写态（保留点按兜底入口），`EDIT` 结束后进入短暂的 `EDIT_RETURN` 回缩动画再回到 `BACK`，两者都直接绘制同一张 `letter_paper.png`，不做另一套背面模板或横线纸；`EDIT` 通过平台多行输入层编辑，并把结果用当前字体套餐直接叠在原图安全书写区内，最多保留 200 个 Unicode 字符。字体资产由 Web/Capacitor 入口在启动主循环前加载并注册为稳定的本地家族，core 只使用套餐定义的族名栈，不访问 DOM 或 `FontFace`。三个套餐分别覆盖温柔手写（霞鹜文楷/悠哉字体）、古典优雅（Noto Serif SC）和浪漫文艺（Cormorant Garamond + 霞鹜文楷）的中英文混排。画师让用户正文使用更小字号（上限约 13px）和较高可见度，让引导句相对放大（上限约 17px）并使用更深苔灰墨色，二者均以 `multiply` 复合方式保留纸纤维；确认/取消按钮独立放在信纸外下方的中间区域，不压住纸面；不添加抖动、轮廓、模糊或阴影；`DRAG` 按位移或速度判定燃烧/回弹；`BURN` 之后忽略用户手势直至复位。

速度由最近若干触点的时间加权计算，坐标全部为逻辑像素；屏高 15% 使用安全区内逻辑高度。燃烧时序以单调累计时间计算，不依赖帧数，后台恢复后将单帧推进量钳制，避免瞬间跳过仪式。

### 3. 图鉴与外观功能保留，图鉴内容只来自真实位图

保留独立图鉴的菜单、收集状态以及信封/纸纹双槽状态，但删除原 24 个 Canvas 静态图案。明信片图鉴由随发行包提供的位图资产目录驱动；当前只有 `assets/envelop/letter_paper.png` 一个有效条目，因此图鉴只显示这一张，不用代码伪造数量或差异。新增图鉴条目必须先加入独立 PNG，再登记资产 ID。主循环、图鉴与手帐直接绘制对应真实位图；Canvas 只负责布局、裁切、折叠、燃烧和克制的外观色调，不得用椭圆、曲线、纯色块、程序化纹理或滤镜组合生成明信片画面。旧 `postcard-01` 至 `postcard-24` 持久化 ID 统一迁移到当前真实资产 ID，以保留手帐记录而不恢复旧图案。测试验证资产目录、迁移、收集、解锁、双槽切换和无程序化图鉴绘制。

### 4. 燃烧使用固定采样遮罩，不创建粒子

明信片先渲染到离屏表面。每帧根据 0–1 的 burn progress 计算一条从上向下的低频扰动火线，使用预分配的固定采样数组构造：

- 火线下方裁剪绘制未烧纸张；
- 火线附近绘制焦黑窄边、卷曲高光及两层受限色焰；
- 火线上方用少量连续纸带做灰白、透明度和轻微上移，表达剥离消散，不生成独立碎屑；
- 结束后只绘制一次径向渐变余光，半径扩张且 alpha 单调下降。

随机扰动由本次明信片 ID 与燃烧序号生成固定种子，确保同一帧重绘稳定，不产生闪烁。火线采样数、纸带数和 draw call 设固定上限，并由性能冒烟锁定。

### 5. 新本地状态使用异步持久化和新键

新增 `letter-burning/state/v1`：`privacyConsent`、按写入顺序排列的 `journalEntries`、`postcardMileage`、`collectedPatternIds`、`unlockedAppearanceIds`、信封/纸纹双启用位、`activeFontPackageId`、`achievements` 与 `statCadenceCount`。为兼容已发布结构，`collectedPatternIds` 与手帐条目的 `patternId` 字段名暂时保留，但其值语义改为真实明信片资产 ID；手帐条目仍为 `{ id, createdAtIso, patternId, text }`，`text` 可为空字符串。使用 `@capacitor/preferences` 的异步读写；Web 开发环境使用 `localStorage` 降级。`Game.start()` 先完成状态 hydration 再开放交互，写入采用串行队列并记录失败状态，防止快速操作覆盖较新的快照。

旧 `money-lai/state/v1` 保留但不读取、不修改，使回滚仍可恢复旧版本；不把金额、钞票图鉴、钱包皮肤或抽钞成就转换成燃信里程、手帐或解锁。

### 6. 输入与隐私状态通过平台适配器

`PlatformAdapter` 增加异步的多行文本编辑、持久化、外部隐私政策打开、临时文件分享、匿名计数和安全随机接口。Web/iOS 上的文字编辑用 adapter 管理的 DOM 覆盖层承接软键盘，确认时保留换行并按 200 个 Unicode 字符截断，不做情绪分析或语义处理；输入期间 core 仍渲染，但屏蔽其他触点。

首次隐私同意是进入游戏前唯一允许的模态流程。同意前不读取手帐、不初始化音频、不请求网络；同意状态只存本机。隐私政策 URL 与计数端点均通过构建配置注入，不写入本机绝对路径或密钥。

### 7. 长图导出已移除（2026-09-29 产品决定）

原方案为「长图只通过系统分享导出」：分块 Canvas 合成临时 PNG 并调起系统分享，不声明照片图库权限。菜单精简时该功能整体下线：导出画师、分享接线与相关文案已删除，`PlatformAdapter` 的 `encodePng`/`shareTemporaryPng` 通用能力契约保留，供未来功能复用；如需恢复须重立规格。

### 8. 匿名计数端点使用时间桶聚合

仓库增加独立 Cloudflare Worker：只接受无请求体的 `POST /burn`，将当前小时的匿名计数加一，并汇总最近 24 个 UTC 小时桶，响应 `{ count: integer }`。时间桶是满足“最近 24 小时”所需的最小近似窗口；只保存聚合整数，不保存单次事件。部署配置关闭应用日志与请求观测，代码禁止 `console`、Cookie、用户代理处理和第三方请求。

客户端只在一次燃烧完成后提交一次，显式 `credentials: omit` 并设置短超时；文字、手帐和本机元进程类型不出现在计数接口参数中。返回失败或无效整数时跳过统计。`statCadenceCount` 只决定第 1、3、5…次是否展示；可见的 `postcardMileage` 单独用于菜单里程、外观解锁和燃信成就，二者都不上传。

### 9. 声景复用合成器，按状态管理总线

保留低音域钢琴规划器和现有软限幅总线；移除钱包与纸币事件接线。新增每次抽信手势第一次有效位移调度一段总长约 1s、实际可听包络约 0.14s 的宽频纸张莎莎声、点燃一次性噪声包络、燃烧低通噪声床与火灭余响。莎莎声使用高低通塑形的噪声和柔和起落包络，前段完成一次明确擦过后保持静默，不做频率扫动或重复脉冲，避免听成连续沙沙、“唰”或“咔咔咔”；同一手势后续移动、停住、松手或回弹不保留循环声，甩出燃烧阶段不复用。首次手势的异步音频解锁期间暂存一枚莎莎声，解锁完成后补播一次，避免第一次有效移动无声。燃烧声由单一长声源配合慢速增益调制，不用离散随机脉冲。钢琴不因燃烧状态停止，火灭时调度一个约 2s 的自然长音。

### 10. 页面与菜单使用同一 Canvas 交互模型

主界面、菜单、明信片里程、图鉴、外观、成就和手帐网格由 core 计算布局与命中，Canvas 绘制保持视觉统一。进入手帐时以 600ms 全屏暖色遮罩渐暗，再切换页面。手帐和图鉴网格虚拟化，只绘制可见行；手帐详情是页内纸面展开层。清空入口位于手帐页页脚，使用明确确认，然后复用燃烧画师处理整页纸面，但不调用公开计数，也不重置本机里程、外观或成就。

### 11. 元进程保留结构、替换材质呈现

本机明信片里程在手帐写入成功后递增，是图鉴收集、外观解锁和成就判定的共同结算点。独立图鉴展示资产目录中实际存在的正面位图，当前仅展示 `letter_paper.png`；外观采用“信封材质/明信片纸纹”双槽，预览和运行时呈现都必须保留 `assets/envelop/` 位图的真实质感。成就包含首次动作、累计燃烧和留白等静态条件，不设置依赖虚构图案数量的收集成就。一次燃烧可能同时产生多项结果，但不排队弹提示，只更新菜单内页面，主界面仍只闪一次手帐入口微光。

### 12. 信封采用统一坐标的分层本地美术资产

以现有铃兰、揉皱棉纸和金色蜡封美术为基准，运行时使用固定文件 `closed_envelope.png`、`open_envelope_back.png`、`open_envelope_front.png`、`letter_paper.png` 与 `background.png` 作为真实材质基底；原始 `open_envelope.png` 只作为分层来源和兼容素材，不再由运行时用几何裁剪模拟前后层。打开信封的后片/内衬与 V 字正面/左右折翼分别导出为两张 1024×1024 RGBA 透明位图，二者保持完全相同的画布、主体边界、中心轴、光源与像素坐标。信纸使用随包 1024×1536 RGBA 竖版画布，运行时按实际纸面内容包围盒取样（不把透明边距缩进卡片），卡片可见宽度锚定打开信封内侧开口并保留约 8% 的左右余量。静置与抽取阶段将同一信纸按水平中线对折：折叠物件保持完整信纸宽度和自然半页高度，使用对应半页源区，不得压缩成窄横条；静置锚点以打开信封位图的开口两侧、V 形最低点和底边共同计算，只露出半页高度约 8%–10% 的上缘，纸底深入 V 形最低点以下并在信封底边前保留余量。信纸素材本身保留温暖旧纸底色、细密纤维、低频褶皱和少量自然折痕，不新增装饰或改变铃兰角饰。释放达到阈值后，同一张纸在 450ms 内移动到展示位，并由上半页作为稳定面、下半页从折线连续展开到自然半页高度。所有仍显示信封的交互阶段固定按“后层 → 信纸 → V 字正面层”绘制，正面层必须最后覆盖信纸与开口重叠的区域，禁止再以单张扁平图加近似多边形裁剪代替真实遮挡。`background.png` 保留 1536×1024 的横向构图与完整暖色纸面，使用不透明像素覆盖视口。竖屏视口由内核在资产加载与视口尺寸变化时离屏合成一次：取避开四角装饰的中央纸面带铺满视口，四角装饰按源纵横比等比移植到视口四角、只向内侧羽化；视口不窄于源图比例时退回纯 cover。

候选阶段不覆盖输入图；确认后的交互物件资产必须具有真实 alpha，而不是白色或棋盘格烘焙背景，背景则必须保持不透明。平台适配层负责随包预加载位图，core 只接收已解码的 `CanvasImageSource`；画师使用统一目标锚点，直接将两个打开信封层夹住信纸。真实连续开合不能直接依赖扁平图插值，后续仍须补充翻盖外侧、内侧与蜡封独立层或中间帧。静态纹理不在每帧重新生成，避免程序化划痕、花纹漂移和无界绘制调用。

视觉方向保留当前资产已有的铃兰、棉纸和金色蜡封，不增加文字、邮戳、照片或新装饰。大胆处只放在纸张实体质感与开合动作，其他界面保持安静。

## Risks / Trade-offs

- [产品替换范围大，旧货币语义容易残留] → 先建立新端到端最小链路，再迁移元进程模型并删除入口不可达的旧模块；用依赖审计与关键词审计阻止钱包、纸币、面额和金额文案进入发行路径。
- [元进程重新引入游戏化压力] → 所有结果静默结算、只在用户主动打开菜单后展示；禁止连续天数、排名、限时、失败和红点催促。
- [精确滚动 24 小时计数与“只存一个整数”无法同时成立] → 端点对外只收发一个匿名增量/整数；服务端内部只保存 24 个匿名小时桶，不保存事件或身份，并在部署说明中写明这一必要实现。
- [Capacitor Preferences 异步化影响启动和测试] → 将 hydration 变成显式启动阶段，平台假实现提供可控 Promise；写入使用单队列避免竞态。
- [火焰易变成高饱和粒子特效] → 色值、火线宽度、采样上限、无粒子和无残留写入快照/画师测试，并以真机录屏作最终判断。
- [输入法与可视视口变化导致布局跳动] → DOM 输入层固定在安全区，记录键盘前逻辑视口，结束后等待一次稳定 resize 再恢复触点命中。
- [依赖系统字体会在模拟器或不同设备回退，造成字迹与信纸分离] → 随发行包内置三组字体套餐与授权文件，入口等待字体解码后再启动游戏；资产测试锁定字体文件、授权和无 CDN 依赖，画师测试锁定套餐族名、`multiply`、中英文混排与全屏编辑回缩后的字号适配。
- [长文本挤出卡片或换行被输入层吞掉] → 平台输入层使用原生多行控件并限制为 200 个 Unicode 字符，画师在全屏编辑区和普通卡片区分别计算可用书写框与字号，退出编辑后用独立回缩相位恢复卡片。
- [Cloudflare 平台默认观测破坏“无日志”] → Worker 配置关闭 observability，不调用日志 API；发布清单要求核对账户级 Logpush/Analytics 设置，未通过则不启用统计端点。
- [产品文案红线被技术错误提示绕过] → 所有用户可见系统文案集中为常量并加入禁词测试，用户原文排除在静态审计之外。
- [独立生成开合资产导致主体和花纹漂移] → 三张交互物件素材使用同一 1024×1024 坐标、主体边界与锚点，先锁定关闭态母版，再以其为引用生成打开态和信纸；背景单独保持 1536×1024 不透明；自动检查尺寸、alpha 与关键锚点，并在三种目标屏幕尺寸复核。若生成模型仍产生像素级漂移，不把两张扁平图冒充连续动画帧，必须补做独立结构层或中间帧。

## Migration Plan

1. 在新分支完成纯状态机、存储 schema 和平台契约，旧入口仍可编译但不再被新 `Game` 使用。
2. 接通信封、明信片、输入与无网络燃烧闭环；通过后再加入手帐、声景与计数。
