## Context

产品定位已从「只写给自己、收好本机」转向「把心里话寄出去」：倾诉需要真实的收件人，收件人收到的应是一只完整的信封——拆开、抽出信纸、听见莎莎声。寄送同时成为里程的意义来源。原「用户内容仅存本机」红线按新定位整体废止；本变更同时承担身份体系、数据架构、后端与收件端体验的落地。

## Goals / Non-Goals

**Goals:**

- 上滑释放后弹出寄送抉择（自绘、不打断 BGM），本地收好与寄出两条去向都落入手帐。
- 寄出只需填写收件人邮箱；后端记录城市级寄送数据并现算里程；邮件经用户邮件客户端发出。
- 收件端拆信页完整复刻主 App 仪式：合封 → 拆封抽纸 → 手写字体原文 → 莎莎声。
- 全部用户绑定数据以服务端为长期存储与唯一事实源，本地仅缓存；重装/换机后登录即全量恢复，数据不丢失。
- 身份 = Apple ID 单一键（Sign in with Apple），首启登录；身份层接口可插拔，安卓留接口暂不实现。

**Non-Goals:**

- 不做密码账号体系、不做短信/邮箱验证码注册。
- 本期不做 IAP 支付（仅预留 appAccountToken 派生规则）。
- 不做正文加密（fragment 用 URL-safe Base64，明文可解码为已接受取舍）。
- 安卓构建不在本期（核心天然跨端，身份层届时接邮箱路径或 Google 登录）。

## Decisions

### 1. 身份：Apple 登录单一键 + 首启登录

首启完成 Sign in with Apple（系统面板两次点击；指纹/面容由设备硬件自定，App 不选择）再进主场景。曾评估「匿名 ID + 延迟登录」，但在全量数据上云的前提下延迟触发点会落在书写仪式中间，且匿名键与 Apple 键并存需要合并逻辑——因此废弃，收敛为单键单门。登录层做成 `IdentityProvider` 平台可插拔接口：iOS 实现 SIWA；安卓仅留接口、暂不实现（将来接邮箱路径或 Google 登录）。Worker 侧校验 SIWA identity token（Apple JWKS 公钥验签）防伪造。将来 IAP 以身份派生的稳定 UUID 作 `appAccountToken`，权益与数据同键。

### 2. 数据架构：服务端为准，本地为缓存

全部用户绑定数据（未寄出草稿、手帐正文、寄送记录、主题选择、字体选择、成就与里程派生数据）存 D1 并与用户绑定；本地 Preferences 仅作离线缓存与写穿队列（离线静默排队、恢复网络补传）。启动登录后从服务端 hydrate；重装/换机登录即全量恢复，任何已留存数据不得丢失。取消/未寄出的草稿作为 `draft` 记录长期留存服务端——本地只是缓存。

### 3. 寄送链路：抉择弹层 → 单输入 → 后端记录 → mailto

上滑达阈值进入 `dispatch` 相位（信纸停展示位），自绘暖纸弹层给两个选择。「存入自己的手帐」走既有 settle（不累计里程）；「寄出」进入输入态，**只填收件人邮箱**（前缀 + 类型下拉 qq/163/126/gmail/outlook/icloud/自定义）——发件人由系统邮件账户承担、发件城市自动取，不设双输入（身份与城市不再依赖发件邮箱后已无必要）。确认后先 `POST /dispatch` 落记录，再以固定主题「你有一封信」+ 拆信引导 `mailto:` 预填发出；随后 settle 折回入袋并落手帐。后端不可用时邮件仍可发出、本地标记「发送失败」、不计累计。

### 4. 城市只记发件端，收件端零索取

评估过「两端城市 + 距离」方案：距离只是装饰性浪漫，代价却是向收件人（第三方）索取浏览器定位——在拆信最亲密的时刻弹权限观感近乎冒犯、拒绝率高，多数记录会残缺。收敛为**只记发件城市**：App 城市级定位一次、经随包城市坐标表反查城市名写入用户档案（设置页可手动改，拒绝授权走手选）；不向收件人索取任何信息、不记录收件城市、不计算距离；IP 地理（VPN/路由偏差不可接受）与域名映射（编造精度）一律禁用。收件人邮箱必填并格式校验，邮件真实发往所填地址（mailto 预填收件人）。

### 5. 后端：Worker + D1，三张表覆盖全部用户数据

Cloudflare 全 serverless：Workers（计算）+ D1（SQLite）。表结构脚本以独立 `.sql` 文件放 `scripts/sql/`，`wrangler.toml` 配 `migrations_dir` 指向该目录，随部署应用、变更历史入 git。累计数不单独存，查询时 `COUNT` 现算、按 Apple identifier 隔离。寄送记录只存发件城市、时间与用户 identifier，不存原始邮箱、正文、收件城市与距离。D1 Time Travel 与导出备份兜底「不丢失」。

只需要三张表，其余概念全部派生：

- `users`：id（Apple identifier）、sender_city、active_theme、active_font、email_hash（可选跨端）、created_at——登录时 upsert。
- `letters`：id、user_id、kind（`draft`→`tucked`/`sent`）、text、created_at、settled_at——每封信一行贯穿生命周期；**手帐 = kind∈(tucked,sent) 的查询视图**；当前草稿即 kind=draft 的行。
- `dispatches`：id、user_id、letter_id、sender_city（**快照**，事后改档案不影响历史）、status（ok/failed）、created_at。

派生而非建表：**里程** = dispatches 的 COUNT；**成就** = 由 letters/dispatches 重算（hydrate 时一次），永远与数据一致。**资源随包、状态上云**：主题 PNG 与字体 ttf 是所有用户相同的素材，随 App 包分发（将来 IAP 素材同属商品内容，走包/商店分发）；用户的选择与权益是状态，存 users 列与权益行——重装/换机登录后 users/letters/dispatches 拉回、成就重算、素材本在包内，零丢失。

### 6. 里程：寄出计数

只有寄出的信累计；本地收好只入手帐。里程页展示累计寄出数与寄送记录列表（发件城市、时间、失败标记）。成就与主题解锁门槛以寄出数计，数值沿用现阈值。

### 7. 收件端拆信页：纯静态零知识页

拆信页为纯静态页面，信内容（正文/日期/主题标记）编码在 URL fragment 的 URL-safe Base64、浏览器本地解码——除静态资源外无任何网络请求，不请求定位或任何权限、不向收件人索取任何信息。体验复刻主 App：合封展示 → 点按拆封 → 信纸抽出展开（同主题资产、手写字体）→ 抽出播 envelop_draw_out.wav 莎莎声（首次点按解锁音频），全程零权限零索取。fragment 缺失/损坏降级为空白信纸致歉页。

### 8. 菜单与设置：变现入口留顶层

菜单六项：里程 / 主题 / 字体 / 成就 / 手帐 / 设置（显示名即「主题」「字体」）。**主题与字体是内容装扮与将来变现入口，保持顶层、不移入设置**；设置页只收系统级项（所在城市、绑定邮箱、隐私政策，将来声音等开关）。不设「已购恢复」入口：权益与数据同键存于服务端，登录即自动恢复——这是服务端为准架构的自然结果。首次隐私同意门随红线废止一并移除（启动直入登录流程）。

## Risks / Trade-offs

- [SIWA 依赖 Apple Developer 账户] — 开发期以 `IdentityProvider` 假实现推进，真接线为独立小任务；真机分发/上架/IAP 收款需付费账户（$99/年）。
- [mailto 依赖系统邮件账户] — 未配置邮件 App 时无法寄出，检测后以本机提示引导，不阻断本地收好。
- [fragment 明文可解码] — 链接只在双方邮箱间流转、服务器零知识；后续可加对称混淆。
- [重装且拒登录] — 无归属会话不可进入（首启登录为门），杜绝产生无法找回的数据。

## Migration Plan

1. 状态机与抉择弹层（本地收好路径先行，寄出按钮暂以「暂未开放」降级）。
2. 身份接口与假实现、数据同步层（D1 建表脚本入 `scripts/sql/`）、后端 dispatch/summary 端点。
3. 寄出输入层与 mailto 编排、里程页改造、同意门移除与首启登录门。
4. 拆信页（纯静态 + fragment + 音频，零索取）。
5. SIWA 真接线（账户就绪后）、设备 QA 与全量回归。
