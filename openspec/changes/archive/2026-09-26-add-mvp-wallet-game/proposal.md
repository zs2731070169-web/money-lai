# 提案：money-lai MVP — 打开钱包，无限抽出现金

## Why

用户（产品所有者）要做一个发布到 Apple App Store 的治愈系休闲小游戏：一部竖屏钱包，用户打开它并从中无限抽出纸币，以「取之不尽的温柔馈赠」带来解压与治愈感。后续计划扩展到微信小游戏与安卓，因此技术底座必须一次选对（跨平台 Web 内核），而非 iOS 原生独占。

## What Changes

- 从零建立项目（当前仓库为空）：TypeScript + Canvas 2D + WebAudio 的平台无关游戏内核，Capacitor 打包为 iOS App。
- 钱包开合交互：**跟手的物理动画**模拟真实钱包翻开（非瞬间画面切换），带阻尼与回弹。
- 抽钞交互：**跟手的拖拽抽出动画**模拟真实抽纸币（非瞬间切换），纸币**无限供应**；提供单击替代（WCAG 2.2 拖拽操作须有点击替代）。
- 治愈金额累计反馈：抽出纸币后累计金额以里程表方式平滑累加（张数为内部状态，不作主画面指标），柔和动效与克制的触觉反馈。
- 程序化合成音效与 BGM（零音频文件）：钱包开合音、纸币抽出音，以及唯美舒缓的生成式钢琴 BGM，风格柔和治愈。
- 治愈系视觉：低饱和暖粉彩、单一柔和光源（左上）、缓慢昼夜色板漂移背景、虚构货币设计（规避真实货币图样合规风险）、统一版画线宽与纸纹颗粒、无 AI 模板感。
- 轻量元进程层（满足 App Store 4.2「持续娱乐价值」的过审深度）：钞票图鉴、8-12 种可解锁钱包/纸币皮肤（参数化绘制，非美术外包）、累计成就、设置页（音效/触觉开关）——以发现式彩蛋呈现，不打断 Zen 主体验。
- 抽取进度会话化：金额与张数不做本地持久化、冷启动清零（每次都是新钱包）；仅元进程状态（图鉴/皮肤/成就/设置）与解锁用内部累计计数器持久化。

**Non-goals（本变更不包含）**：账号系统、内购/广告（v1 完全免费，保住治愈定位与 Data Not Collected 隐私标签）、分享、Game Center、微信小游戏与安卓端的实际打包发布（仅在架构上预留 PlatformAdapter 适配层）。

## Capabilities

### New Capabilities

- `wallet-interaction`: 钱包开合手势与物理动画——翻盖跟手旋转、阻尼回弹、开合状态机。
- `cash-drawing`: 抽钞手势与游戏循环——跟手拖拽抽出、无限供应、单击替代、计数累加与持久化。
- `game-visuals`: 治愈系视觉规格——场景配色、光影、虚构纸币设计、排版（圆体数字）、动效原则与无 AI 模板感约束。
- `procedural-audio`: WebAudio 程序化音效——开合音与抽钞音的合成规格、音量/并发控制、iOS 首次手势解锁。
- `platform-adaptation`: 跨平台适配——内核/平台适配层分离（音频、触觉、持久化、画布、输入）、iOS 安全区与 DPR 处理、Capacitor 壳。
- `meta-progression`: 轻量元进程——钞票图鉴、皮肤解锁、累计成就、设置页，满足过审深度的同时不打断 Zen 主循环。

### Modified Capabilities

（无——全新项目，尚无存量规格。）

## Impact

- **代码**：全新仓库脚手架（Vite + TypeScript + Vitest + Capacitor），无存量代码受影响。
- **依赖**：运行时零第三方渲染/音频库（原生 Canvas 2D + WebAudio）；构建链 Vite/Vitest/Capacitor。
- **系统**：iOS App（WKWebView）；架构约束——游戏内核不得直接调用平台 API，须经适配层。
- **合规**：纸币必须为虚构设计（规避人民币图样管理等法规，禁用真实货币完整/局部图案、真实行名与人像）；App 按 4+ 分级、无账号无追踪（Data Not Collected）的最小隐私方案设计；中国区上架需完成工信部 App 备案（ICP 备案号），作为发布前置条件列入验收。
