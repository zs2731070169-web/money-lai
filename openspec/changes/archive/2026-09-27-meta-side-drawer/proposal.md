# 提案：元进程入口改版为右侧滑出抽屉 + 汉堡入口按钮

## Why

用户实测反馈：图鉴/皮肤/成就/设置四个页签挤在居中面板顶部的形态不理想，希望改为**侧边弹出菜单**；右上角元进程入口的「圆圈+圆点」图标语义不明、看起来奇怪。抽屉是移动端承载这类二级集合页的常规容器，且能把主画面的侵入感降到最低（入口即整个菜单）。

## What Changes

- **容器改版**：元进程覆盖层从「居中面板 + 顶部 4 标签」改为**右侧滑出抽屉**——右上角入口触发，抽屉自右缘滑入，底部衬（scrim）点按关闭。
- **两级导航**：抽屉首屏为菜单列表（图鉴/皮肤/成就/设置四行）；点选后在抽屉内展示对应页面，页面头部提供「‹ 返回」回菜单；隐私页仍从设置页进入。
- **入场按钮重绘**：右上角入口从圆圈+圆点改为**汉堡菜单图标**（墨青描线三横，44×44 命中），仍满足 game-visuals「角落轻量图标」条款。
- **滑入/滑出动画**：抽屉以 ~180ms/~140ms 进出场（画布内平移，进度驱动布局纯函数），动画期间仅底衬可点（关闭），按钮在完全展开后才参与命中——延续「看到的 = 可点的」单一事实源纪律。
- **右滑收回**（实测反馈追加）：抽屉上向右滑动超过定向阈值（24px 横移且大于纵移）即触发关闭，信号语义不跟手。
- **页内容复用**：图鉴/皮肤/成就/设置四页内容绘制沿用现有画师逻辑，仅重排进抽屉内容区（皮肤网格在窄抽屉内改 2 列）。
- 不新增音频/触觉/手势（最小闭环；后续实测反馈再加）。
- **抽屉动画性能（实测反馈追加 2026-09-27：滑入/滑出偶发卡顿）**：
  ① 页面数据（图鉴/皮肤/成就/设置映射）与皮肤 id 列表改为按内容签名缓存，
  消灭动画帧上的对象分配（GC 间歇卡顿源）；② 面板+shadowBlur 投影预渲染进离屏缓存层
  （同样的光栅化参数，像素与逐帧绘制一致；样式零变化——实测反馈纠偏：曾改为左缘渐隐
  暗条被用户打回），动画帧一次 drawImage 合成；无离屏能力时走原样式慢路径。
- **轻提示不压抽屉**（实测反馈追加 2026-09-27）：解锁皮肤/达成成就的自动淡出轻提示
  在抽屉打开（含开合动画）期间不绘制——不遮挡菜单页面；抽屉关闭后未过期的提示
  继续淡出。提示时龄按自然时钟推进（抽屉内停留耗尽即静默消失，解锁结果仍见于列表页）。

## Capabilities

### New Capabilities
（无）

### Modified Capabilities
- `meta-progression`：ADDED「元进程抽屉容器」需求——入口语义、抽屉几何、两级导航、关闭方式、动画期命中规则。
- `game-visuals`：MODIFIED「极简画面构成」——主画面静置约束不变，显式允许按需唤出的瞬态元进程抽屉（非持久 HUD），入口图标条款明确为汉堡形态。

## Impact

- 代码：`src/core/meta/overlay-layout.ts`（布局重写为抽屉几何 + 菜单/页面两级 + 进度偏移）、`src/core/render/overlay-painter.ts`（抽屉铬件/菜单行绘制，页内容重排）、`src/core/game.ts`（入口图标重绘、抽屉开合动画状态、命中路由）。
- 测试：新增 `tests/meta/drawer-layout.test.ts`（几何/命中纯函数单测，当前覆盖层无专属单测，本次补齐）；`tests/wallet/tap-routing.test.ts` 视入口命中变化扩展。
- 规格：两能力增量如上；成就条款「可经设置入口查看」由抽屉一级入口天然满足（成即为菜单直接项）。
- 部署纪律修正：iOS 部署链在 `cap sync` 前必须 `npm run build`（本次实测发现跳过会同步过期 dist，模拟器呈现幽灵旧 UI）。
